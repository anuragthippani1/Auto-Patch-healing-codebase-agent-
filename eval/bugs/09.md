LRU cache evicts entries that were just used

Our cache hit rate dropped sharply. Entries that are in constant use are being evicted while stale ones stay.

Reading an entry does not seem to count as a use:

    >>> from toolkit.cache import LRUCache
    >>> cache = LRUCache(2)
    >>> cache.put("a", 1)
    >>> cache.put("b", 2)
    >>> cache.get("a")
    1
    >>> cache.put("c", 3)
    >>> "a" in cache
    False

I expected `"b"` to be evicted, because `"a"` was read more recently.

Updating an entry has the same problem. If I replace `cache.get("a")` above with `cache.put("a", 10)`, then `"a"` is still the one that gets evicted when `"c"` is added.

The class documentation says both reading and writing an entry count as a use.
